# st-zrt 0.3.0 local release checklist

The release candidate was committed locally only after explicit approval. The following gates are
reproducible and do not mutate a tag, registry, or remote.

## Local prerequisites

- Rust stable with `rustfmt`/Clippy plus the `1.85.1` toolchain.
- `cargo-deny` 0.19.x or 0.20.x (matching the pinned `cargo-deny-action` container).
- CPU and CUDA 13 ONNX Runtime paths/toolkit for native GPU gates; `compute-sanitizer` for sanitizer coverage.
- A network connection for advisory/index refresh and publication dry-runs. Package source inventories themselves do not upload.

## New required regression gates (0.3.0 hardening)

These gates were added with the hardening worktree and must pass before the next approved commit:

- CUDA regression `cuda_graph_prebuilt_bucket_first_run_is_replay_not_capture_while_sibling_replays`
  (`cargo test -p st-zrt --features cuda --test cuda_ep`): prebuilt CUDA-graph buckets must be
  eagerly captured, so the first served run of a prebuilt bucket is a replay, never a capture
  overlapping a sibling replay.
- `cargo deny --manifest-path bench/Cargo.toml check` and
  `cargo deny --manifest-path bench-c/Cargo.toml check`: dependency policy now covers the
  auxiliary benchmark graphs (wildcard/unknown-registry/unknown-git deny).
- Canonical lockfile-source/unused-patch rejection now covers `bench/Cargo.lock` as well as
  `Cargo.lock` and `bench-c/Cargo.lock` (CI and `release-check.sh local`).

**The exact post-hardening full local gate must be rerun from scratch on the final reviewed
worktree** — the evidence below predates the build-script, CI, docs, and eager-capture changes and
does not certify them.

## Before a local commit

- Verify the `CHANGELOG.md` 0.3.0 release date and package versions are final for the approved commit.
- `scripts/release-check.sh local` (includes Rust 1.85.1 MSRV, compile/rustdoc/doctest feature matrix, cargo-deny, canonical lockfile-source/unused-patch rejection, package licenses, workspace all-target/all-feature Clippy/rustdoc, and CUDA benchmark-workspace checks)
- `cargo deny --manifest-path bench/Cargo.toml check` and `cargo deny --manifest-path bench-c/Cargo.toml check`
- `cargo test -p st-zrt --tests --all-features` (CUDA tests serialize full CUDA lifetimes around graph capture)
- `cargo test -p st-zrt --features cuda --test cuda_ep` (eager-capture regression)
- `scripts/compute-sanitizer-zrt.sh`
- `scripts/soak-zrt.sh`
- `cargo publish -p st-zrt-sys --dry-run --allow-dirty --locked`
- `cargo package -p st-zrt --list --allow-dirty --locked` (manifest inventory only until sys 1.27.1 is published)
- Celer: `cargo test --workspace --locked`
- Celer: `cargo check --workspace --all-targets --features cuda --locked`
- `git diff --check` in both repositories

## Approval boundaries

1. Ask before creating a local st-zrt commit.
2. Test that exact commit; ask separately before any tag, push, or publication.
3. Before publishing either crate, ensure the public default branch contains the release docs linked by the packaged READMEs (`CHANGELOG.md`, `docs/architecture.md`, `docs/cuda-graph-paths.md`, and `docs/v0.3-benchmark-results.md`); crates.io freezes those `blob/main` links for each version.
4. Publish `st-zrt-sys 1.27.1` first, then attempt the final `st-zrt 0.3.0` package verification: the wrapper intentionally requires the revised registry dependency. Strict order: `st-zrt-sys 1.27.1` → `st-zrt 0.3.0`, cut from tag `st-zrt-v0.3.0` (the default tag derived from the workspace version by `scripts/release-check.sh`).
5. Only after an immutable st-zrt revision is remotely reachable, replace Celer's local path patch
   with a full Git SHA (or remove it after the 0.3.0 crate is published), regenerate the lockfile, and
   validate standalone CI/Docker resolution.
6. Ask separately before committing or pushing the Celer dependency transition.

Never use a branch name, mutable tag, or machine-local path for the final Celer dependency.
