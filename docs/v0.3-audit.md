# st-zrt v0.3 audit

> **Status: HISTORICAL, UNPUBLISHED (read as evidence only).** This audit was written against a
> 0.3-era working tree that was never released; it predates the final `ServingLane`/
> `DynamicIoRuntime` consolidation, the `BufferSpec` buffer policy, `CudaConfig`, and the
> `st-zrt-sys 1.27.1` binding revision. Line numbers and API names below describe that snapshot
> and are not current guidance. Current design: [`architecture.md`](architecture.md) and
> [`cuda-graph-paths.md`](cuda-graph-paths.md).

- **Branch:** `chore/st-zrt-0.3-audit` (forked from `chore/st-zrt-0.2.1` @ `d15282b`)
- **Scope:** whole crate — `st-zrt/src` (~20k LOC, 29 files). st-zrt-sys bindings are out of scope.
- **ORT target:** 1.27 only (single version, v0.2 onward).
- **Method:** four read-only analysis agents (concurrency/soundness, performance, duplication,
  API/correctness), then every headline finding was re-verified against source before being kept.
  Two agent **HIGH** claims were rejected on verification (see [Rejected findings](#rejected-findings)).

Findings are tiered **P0** (correctness / hot-path), **P1** (high-value), **P2** (polish).
Progress is tracked at the bottom: [Progress](#progress).

## P0 — correctness / hot-path

### C1 — `run_unsynchronized` silently drops the device-input refresh
`src/runtime.rs:599-612` — `StaticIoLane::run_unsynchronized` skips the host→device copy and the
stream sync that `run` performs in device-input mode. On a device-input lane it therefore replays the
cuda-graph over **stale** device buffers with no synchronization. The doc warns, but nothing errors.
**Fix:** return an error when `device_inputs.is_some()`. _Severity: correctness, HIGH._

### C2 — cuda-graph eviction races concurrent replay on a shared session
`src/runtime.rs:2243-2272` calls `Session::release_captured_graph(id)` (`src/session.rs:756`) from
`DynamicIoRuntime::evict_one_bucket_if_full`. Eviction borrows the runtime `&mut self`, but the
session is a shared `Arc<Session>` that other threads may be replaying that same `graph_id` on. The
`&mut self` does not serialize against in-flight `Run`s. **Fix:** confirm ORT-1.27 guarantees
`SessionReleaseCapturedGraph` is safe against a concurrent replay of that id; otherwise gate eviction
behind a per-graph in-flight count. _Severity: soundness, treat HIGH until confirmed._

### P1 — per-read tensor re-introspection on the hottest path
`src/tensor.rs:92-113` (`TensorView::as_slice`) + `src/memory.rs:236-273`
(`snapshot_from_ptr`/`ensure_value_host_accessible`). Every `as_slice`/`as_bytes`/`as_mut_slice`
calls `tensor_type_and_shape()` (handle alloc+release) and rebuilds a full `MemoryInfoSnapshot`
(name `String` alloc + ~8 FFI calls) just to test host-accessibility — ~11 FFI calls + 2 allocs per
custom-op input read and per engine-output slice read. `TensorBuffer` already proves this can be a
zero-cost borrow. **Fix:** cache element-type/count + a host-accessible flag on the owning wrapper.
_Severity: perf, HIGH — single biggest throughput win._

## P1 — high-value

### E1 — no `Debug` on primary types
`Session`, `OwnedValue`, `Tensor`, `TensorView`, `IoBinding`, `RunOptions`, `Environment`,
`RunFuture`, … none implement `Debug` — users can't `dbg!()`. Needs *manual* impls (opaque handles,
not a bare `derive`). _Severity: ergonomics, MEDIUM._

### E2 — `StaticIoLanePool` mutex poison is fatal
`src/runtime.rs:921,928,938,946,997` — every `checkout`/`try_checkout`/guard-`drop`/`idle_count` does
`.lock().unwrap()`. A poisoned mutex bricks the entire pool. Low probability (critical sections hold
no user code), but a serving pool that dies on one panic is bad. **Fix:** recover via
`unwrap_or_else(|e| e.into_inner())`. _Severity: robustness, MEDIUM._

### E3 — custom-op accessors return raw owning FFI handles
`src/custom_ops.rs:~523-851` (verify lines) — `KernelInfo`/`KernelContext` accessors return
`*mut TypeInfoHandle`/`ValueHandle`/`AllocatorHandle` with "release with `Release*` when done" docs —
a manual-free footgun in a safe wrapper. **Fix:** return owning wrappers or make raw variants
`pub(crate)`. _Severity: API safety, MEDIUM._

### E4 — `CudaPreset::CudaGraph` omits `user_compute_stream`
`src/ep.rs:147-153` — the preset enables cuda-graph but does not set `user_compute_stream`, which the
device-input refresh path needs. **Fix:** document the requirement, or add a
`CudaGraph { device_id, stream }` variant (confirm how device-input lanes obtain their stream first).
_Severity: API/footgun, MEDIUM._

### E5 — `training` feature is passthrough-only
`Cargo.toml:43,49` — `grep 'feature = "training"' src/` is empty: the safe layer exposes no training
API, yet the feature is advertised and built on docs.rs. **Fix:** expose an API or drop it from
`st-zrt` (keep the toggle in `st-zrt-sys`). _Severity: API honesty, LOW-MEDIUM._

## P2 — polish / duplication / stale

### D1 — lane-layer combinatorics duplication (~250-300 lines)
`src/runtime.rs:1652-1870`, `src/session.rs:2096-2455` — 7 `StaticIoRuntime` ctors,
`run_with_allocator_stats` byte-identical ×5, lane index-accessors ×7/type, `prime()` byte-identical
×2, 6 `Session::new_with_*` scaffolds. **Fix:** `macro_rules!` / sealed-trait default methods.

### D2 — seven `zeros_aligned_*` constructors
`src/tensor.rs:785-870` — 3 flag bits (hugepage/prefault/mlock) × boilerplate. **Fix:** one private
`zeros_aligned_flags(..)` + seven one-liner delegators (~40 lines saved).

### D3 — stale `#[allow(dead_code)]` on `serde_support::opt_cstr`
`src/serde_support.rs:20` — the module is used (`ep.rs` ×6, `session_options.rs`). The attribute
suppresses a warning that no longer fires. **Fix:** delete the line.

### D4 — serde silently drops `user_compute_stream` on round-trip
`src/ep.rs:~130-131,264-268` — pointer-valued options are `serde(skip)`, so a deserialized config
loses the stream with no warning. **Fix:** document that pointer options aren't serializable.

### D5 — `CudaStream::drop` destroys without syncing
`src/cuda_rt.rs:~108-115` — best-effort `cudaStreamSynchronize` before `cudaStreamDestroy` for
caller-misuse safety.

## Rejected findings

Verified-against-source and dropped:

- ❌ **RunFuture drop leaks outputs** — `OwnedValue` has `impl Drop` (`tensor.rs:2309`) that releases
  the ORT handle; when `AsyncState`'s last `Arc` ref drops, the result cell and its `Vec<OwnedValue>`
  are freed. No leak on normal completion. Narrow caveat: a leak only if the `RunAsync` callback
  *never fires* (ORT worker lost) — an ORT-contract concern, not the claimed bug.
- ❌ **`tensor_at`/`tensor_mut_at` are UB** — ORT's `TensorAt` validates index bounds and returns an
  error status; the fns are safe `Result`-returners (`tensor.rs:2011-2027`). Optional nicer-error
  pre-check only.
- ❌ **`DeviceValue` has a needless `Deref`** — no `Deref` exists; the explicit forwarders are an
  intentional force-explicit-placement design.
- ❌ **"`pub use st_zrt_sys as sys` is a boundary defect"** — it's actively used by the public API
  and tests (`st_zrt::sys::ElementType::Float`, …). Design note only.

### Resolution log

_(appended per fix as it lands)_

- **C1** — `StaticIoLane::run_unsynchronized` now returns an error when `device_inputs.is_some()`
  instead of silently skipping the H2D refresh + stream sync. Doc updated to state it errors in
  device-input mode. Verified: fmt + clippy clean (default `ep`); `static_io_lane_runs_unsynchronized_
  host_binding` still green (host path unaffected). `runtime.rs:593-612`.
- **C2** — captured CUDA graph ids are now allocated from a process-global session allocator instead
  of a runtime-local counter, and graph-backed static-lane runs take a per-session in-flight guard.
  `Session::release_captured_graph` blocks new tracked replays for that id, waits for active tracked
  replays to drain, then calls ORT release. `DynamicIoRuntime` eviction uses the session allocator.
- **P1** — `TensorView`, `AllocatedTensor`, and `OwnedValue` now cache immutable tensor metadata
  (element type/count/byte length/host-accessible flag). Host-accessibility probing is allocation-free
  on hot output stamping; detailed placement errors still use the full snapshot on the error path.
- **E1** — added manual `Debug` impls for the primary opaque/runtime/value types (`Session`,
  `OwnedValue`, `Tensor`, `TensorView`, `IoBinding`, `RunOptions`, `Environment`, `RunFuture`,
  serving lanes/runtimes, and custom-op wrappers).
- **E2** — `StaticIoLanePool` mutex/condvar paths recover poisoned mutexes with `into_inner()`.
- **E3** — custom-op safe accessors no longer return manual-free owning FFI handles:
  type-info accessors return `RuntimeTypeInfo`, tensor attributes return `OwnedValue`, constant inputs
  return borrowed `TensorView`, and allocators return a borrowed wrapper.
- **E4/D4** — `CudaPreset::CudaGraph` now carries `user_compute_stream` and the lockless serving
  builder passes each lane stream through the preset. Pointer-valued CUDA options are documented as
  skipped by serde and must be reattached after deserialization.
- **E5** — removed the passthrough-only `training` feature from `st-zrt` and docs.rs feature list.
- **D1** — collapsed repeated lane allocator-stats and prime loops into internal helpers; kept public
  constructor scaffolding explicit to preserve doc locality and avoid macro-heavy API docs.
- **D2** — consolidated `zeros_aligned_*` constructors through one private flag helper preserving
  hugepage → prefault → mlock ordering.
- **D3** — removed stale `#[allow(dead_code)]` from `serde_support::opt_cstr`.
- **D5** — `CudaStream::drop` now best-effort synchronizes before destroying the stream.
- **Verification** — `cargo fmt --all`; `cargo check -p st-zrt`; `cargo check -p st-zrt --features
  serde,custom-ops,model-editor`; `cargo check -p st-zrt --features cuda`; `cargo clippy -p st-zrt
  --all-targets -- -D warnings`; `cargo clippy -p st-zrt --all-targets --features
  serde,custom-ops,model-editor -- -D warnings`; `cargo clippy -p st-zrt --all-targets --features
  cuda -- -D warnings`; `cargo test -p st-zrt`.
