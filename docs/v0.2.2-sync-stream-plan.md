# v0.2.2 Sync Stream Plan

> **Historical note:** the original borrowed `SyncStream<'env>` design below was superseded in the
> later unpublished worktree that became st-zrt 0.3.0. `EpDevice` now retains its originating `Arc<EnvInner>`, `SyncStream` is returned in
> an `Arc`, and pure/frozen run options own that stream guard. The inventory remains useful, but the
> borrowed-pointer lifetime contract is no longer the current API.

## What ORT 1.27 Exposes

The generated FFI already contains the relevant raw API entries:

| ORT API | Index | Notes |
| --- | ---: | --- |
| `CreateSyncStreamForEpDevice` | 383 | Creates an `OrtSyncStream` for an `OrtEpDevice`. |
| `SyncStream_GetHandle` | 384 | Returns the native EP stream handle as `void*`. |
| `ReleaseSyncStream` | 385 | Releases the stream. |
| `CopyTensors` | 386 | Accepts an optional `OrtSyncStream*`; ZRT currently passes null. |
| `RunOptionsSetSyncStream` | 413 | Attaches a sync stream to `OrtRunOptions`. |

The EP sub-API also exposes optional sync diagnostics:

- `SyncStream_GetImpl`
- `SyncStream_GetSyncId`
- `GetSyncIdForLastWaitOnSyncStream`

Related ZRT surface that already exists:

- `IoBinding::synchronize_inputs`
- `IoBinding::synchronize_outputs`
- `Session::run_binding_unsynchronized`
- `Lane::run_unsynchronized`
- `StaticIoLane::run_unsynchronized`
- `CudaProviderOptions::user_compute_stream`
- `ExternalResourceImporter::{wait_semaphore, signal_semaphore}` with raw `OrtSyncStream*`
- `CustomOpKernelContext::gpu_compute_stream`

## Release Hygiene

- Fix the generated `ReleaseOpAttr` feature gate so `st-zrt` builds with `model-editor` without requiring the unrelated `custom-ops` feature. Downstream `rs-celer` currently enables `custom-ops` only as a temporary workaround for published `st-zrt` 0.2.1.

## Proposed Public API

Keep the API narrow and explicit:

```rust
pub struct SyncStream<'env> {
    raw: *mut sys::SyncStreamHandle,
    _env: PhantomData<&'env Environment>,
}

impl<'env> SyncStream<'env> {
    pub fn for_ep_device(
        env: &'env Environment,
        device: &EpDevice,
        options: &[(&str, &str)],
    ) -> Result<Self>;

    pub fn native_handle(&self) -> *mut c_void;

    #[cfg(feature = "model-editor")]
    pub fn sync_id(&self) -> Option<u64>;
}

impl Drop for SyncStream<'_> {
    fn drop(&mut self);
}
```

Run-options integration:

```rust
impl RunOptions {
    pub fn set_sync_stream(&mut self, stream: &SyncStream<'_>) -> &mut Self;
}
```

Copy integration:

```rust
impl Session {
    pub fn copy_value_to_tensor_buffer_on_stream<T: TensorElement>(
        &self,
        src: &OwnedValue,
        dst: &mut TensorBuffer<T>,
        stream: &SyncStream<'_>,
    ) -> Result<()>;

    pub fn copy_value_to_allocated_tensor_on_stream<T: TensorElement>(
        &self,
        src: &OwnedValue,
        dst: &mut AllocatedTensor<T>,
        stream: &SyncStream<'_>,
    ) -> Result<()>;
}
```

Interop integration should replace raw stream pointers with borrowed `SyncStream`:

```rust
impl ExternalResourceImporter {
    pub fn wait_semaphore_on_stream(
        &self,
        semaphore: &ExternalSemaphoreHandle,
        stream: &SyncStream<'_>,
        value: u64,
    ) -> Result<()>;

    pub fn signal_semaphore_on_stream(
        &self,
        semaphore: &ExternalSemaphoreHandle,
        stream: &SyncStream<'_>,
        value: u64,
    ) -> Result<()>;
}
```

## Safety Contract

The wrapper must make these rules explicit:

- `SyncStream` is tied to the `Environment` whose EP devices were discovered.
- `EpDevice` remains borrowed from ORT and must not be released by ZRT.
- `SyncStream::native_handle()` is opaque and EP-specific. ZRT must not interpret it.
- `RunOptions::set_sync_stream` must not outlive the stream used for a run. Prefer requiring the
  caller to keep `SyncStream` borrowed for the run rather than storing it in a session-level default.
- Stream-based `CopyTensors` must remain explicit and fallible. Do not add hidden host fallback on a
  stream path.
- Existing synchronized APIs remain the default. Stream APIs are expert-level opt-ins.

## Tests Required Before Release

CPU-only tests:

- `SyncStream::for_ep_device` returns a clean error or skip when no EP device exists.
- `RunOptions::set_sync_stream` reaches FFI only when a stream was created.
- `Drop` releases a null/non-null stream cleanly where construction succeeds.

CUDA tests:

- Discover CUDA `EpDevice`.
- Create `SyncStream` for that device.
- Attach stream to `RunOptions` and run a CUDA session with IoBinding.
- Bind preallocated CUDA `AllocatedTensor` outputs and verify they remain non-host-readable.
- Try `CopyTensors` on stream for supported device/host or device/device routes. If ORT returns
  "transfer implementation not found", assert the error is clear and no hidden fallback occurs.
- Compare synchronized vs unsynchronized binding with and without `RunOptions::set_sync_stream`.

Interop tests, if a graphics handle fixture exists:

- Import external semaphore.
- Wait/signal using `SyncStream`.
- Confirm sync-id diagnostics are nonzero or monotonic when supported.

## Benchmarks Required

Add CUDA-focused benches, separate from CPU wrapper regression benches:

- `cuda_iobinding_preallocated_output_sync`
- `cuda_iobinding_preallocated_output_unsync`
- `cuda_iobinding_preallocated_output_run_options_stream`
- `copy_tensors_device_to_device_null_stream`
- `copy_tensors_device_to_device_sync_stream`

Report p50/p99/p999 and whether ORT inserted host/device copies.

## Non-Goals

- Do not expose stream ownership for arbitrary raw CUDA streams beyond existing
  `CudaProviderOptions::user_compute_stream`.
- Do not promise CUDA-to-host `CopyTensors` support for every ORT build.
- Do not make unsynchronized APIs the default.
- Do not add stream APIs to `v0.2.1`.

## Decision

ORT 1.27 has enough raw API surface for a narrow `SyncStream` wrapper. The wrapper is justified only
with CUDA tests that prove stream attachment and stream-based copies behave correctly. Until then,
keep `v0.2.1` on the current narrow escape hatch: explicit synchronized IoBinding by default plus
opt-in unsynchronized lane runs.
